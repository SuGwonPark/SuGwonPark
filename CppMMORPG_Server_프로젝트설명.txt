==============================================================
 C++ MMORPG 서버 개인 프로젝트
==============================================================

기간      : 2026-09 ~ 진행 중
인원      : 1인 개발 (서버 전체 설계 및 구현)
사용 언어 : C++
네트워크  : Boost.Asio 기반 TCP 비동기 I/O
DB        : MySQL (X DevAPI)
개발 환경 : Visual Studio, vcpkg, Git
기타      : libsodium(비밀번호 해시), magic_enum


--------------------------------------------------------------
1. 프로젝트 소개
--------------------------------------------------------------
7년간 Node.js로 라이브 서비스 서버를 개발·운영하면서 이벤트 루프
기반 구조의 한계를 체감했고, 스레드 모델과 메모리를 직접 설계하는
실시간 서버를 만들기 위해 C++ MMORPG 서버를 처음부터 개발하고
있습니다.

타겟형과 논타겟형 전투를 함께 지원하는 3D MMORPG를 목표로,
로그인부터 캐릭터 생성·선택, 존 입장, 이동, 전투, 스킬, 보상,
필드 드롭, 인벤토리, 장비, 존 이동까지 MMORPG 서버의 기본 흐름을
직접 구현했습니다.


--------------------------------------------------------------
2. 서버 구조
--------------------------------------------------------------

  [Client] ──TCP──▶ [Gateway Server] ──TCP──▶ [Zone Server]
                        │                        │
                        │ 로그인 / 캐릭터         │ 게임 로직
                        │ 세션 관리               │ (존 × 채널)
                        ▼                        ▼
                    [Account DB]             [Game DB]

  - Gateway Server
    클라이언트 접속, 로그인, 캐릭터 목록·생성·선택, 세션 관리.
    게임 패킷은 해당 Zone으로 전달하고, Zone의 응답을 클라이언트로
    중계합니다.

  - Zone Server
    존·채널 단위로 게임 로직을 처리합니다. 시작 시 Gateway에 접속해
    자신이 가진 존·채널 목록을 등록합니다.

  - ServerCore (정적 라이브러리)
    두 서버가 공유하는 네트워크 버퍼, DB 스레드 풀, 작업 큐,
    패킷 정의, CSV 로더, 공용 템플릿.

  - BotClient
    부하 테스트용 봇 클라이언트.

3. 폴더 구조
--------------------------------------------------------------

server/
 ├ cppProject.sln          솔루션 파일
 │
 ├ GatewayServer/          게이트웨이 서버 (클라이언트 접속 창구)
 │  ├ Game/                계정 처리: 로그인, 캐릭터 목록·생성·선택 (Account)
 │  ├ Manager/             세션 관리(SessionManager), 존·채널 목록과
 │  │                      패킷 전달 대상 관리(ZoneManager)
 │  ├ Network/             클라이언트 접속 수락(Server)과 클라이언트 세션
 │  │                      (ClientProxySession), Zone 서버 접속 수락
 │  │                      (InternalServer)과 Zone 세션(ZoneServerSession)
 │  └ Main.cpp             DB 연결, 템플릿 로드, 서버 시작
 │
 ├ ZoneServer/             존 서버 (실제 게임 로직)
 │  ├ World/               존과 공간 관리: Zone(작업 큐 기반 존 로직),
 │  │                      ZoneCombat(존 안의 공격·스킬 처리),
 │  │                      AoiGrid(시야 격자), ZoneConstants(존 상수)
 │  ├ Object/              월드에 존재하는 객체: Player, Monster
 │  ├ Item/                아이템: Inventory(인벤토리·장비 슬롯),
 │  │                      ItemUID(아이템 고유 번호 발급)
 │  ├ Combat/              전투 계산: Combat(스탯·치명타·방어·공격속도·
 │  │                      스킬 수치 공식), CombatStat(전투 스탯 구조),
 │  │                      HitArea(원·부채꼴·직선 범위 판정)
 │  ├ Network/             Gateway 접속과 내부 패킷 송수신(GatewaySession)
 │  ├ Template/            CSV 기획 데이터 템플릿 (존, 포탈, 몬스터, 스폰,
 │  │                      보상, 스킬, 스킬 효과, 레벨, 스탯, 아이템,
 │  │                      아이템 옵션) 과 일괄 로드·검증(Template)
 │  └ Main_Zone.cpp        템플릿 로드, 존·채널 생성, 틱 타이머, 종료 처리
 │
 ├ ServerCore/             두 서버가 함께 쓰는 공용 라이브러리
 │  ├ DB/                  DB 스레드 풀(DBThreadPool), 계정 DB(AccountDB),
 │  │                      게임 DB(GameDB) 작업 큐
 │  ├ JobSystem/           작업 큐(JobQueue), 단일 논리 스레드 직렬화
 │  │                      (JobSerializer), 워크 스틸링 스레드 풀
 │  ├ Manager/             송신 버퍼 생성 도우미(SendBufferManager)
 │  ├ Network/             송신 버퍼(SendBuffer)
 │  ├ Protocol/            패킷 번호(PacketID), 패킷 구조체(Packets),
 │  │                      공용 데이터 타입(ProtocolTypes), 열거형(VarEnum),
 │  │                      Gateway↔Zone 내부 패킷(InternalPackets)
 │  ├ Template/            Gateway와 Zone이 함께 쓰는 템플릿 (Character)
 │  └ Utils/               실행 설정 로드(Config), CSV 읽기(CsvReader),
 │                         난수·enum 변환 등 공용 함수(util)
 │
 ├ BotClient/              부하 테스트용 봇 클라이언트
 ├ Data/                   CSV 기획 데이터 (서버 시작 시 로드)
 ├ Config/                 실행 설정 파일 (server.ini: 포트, Gateway 주소)
 └ DB/                     DB 스키마 SQL (account, game)


--------------------------------------------------------------
4. 주요 구현 내용
--------------------------------------------------------------

[동시성 구조]
  - Zone 하나를 하나의 작업 큐(JobSerializer)로 처리하는 단일 논리
    스레드 구조. 게임 로직 안에서는 락 없이 상태를 관리합니다.
  - DB 작업은 별도 DB 스레드 풀에서 실행하고, 결과는 다시 Zone 작업
    큐로 넘겨 처리합니다. 게임 틱이 DB 응답을 기다리지 않습니다.
  - Gateway의 세션별 송수신은 strand로 직렬화합니다.

[네트워크 / 패킷]
  - 고정 크기 헤더(size, id) 기반 패킷 파싱, 1바이트 정렬 구조체로
    패킷 정의, 가변 길이 목록 패킷(헤더 + 개수 + 배열).
  - 세션 상태 머신(접속 → 로그인 → 로비 → 게임)으로 단계별로 허용된
    패킷만 처리.
  - 송신 큐가 일정 크기(1MB)를 넘는 느린 클라이언트는 연결을 종료해
    서버 메모리 증가를 방지.

[AOI(시야) 처리]
  - 3×3 격자 기반 AOI로 주변 유저에게만 이동·전투·드롭 패킷을 전송.
  - 칸이 바뀔 때만 새로 보이는 칸 / 안 보이게 된 칸의 차이를 계산해
    등장·퇴장 패킷을 전송.
  - 플레이어, 몬스터, 필드 드롭을 각각의 격자로 관리.

[Gateway 멀티캐스트]
  - Zone이 여러 유저에게 같은 패킷을 보낼 때, 대상 세션 목록과
    페이로드를 내부 패킷 하나로 묶어 Gateway에 전달.
  - Gateway는 송신 버퍼 하나를 모든 대상 세션이 공유해 복사와 내부
    통신량을 줄임.

[전투]
  - 타겟형 + 논타겟형 혼합: 대상 지정 공격과, 방향 기반 범위 판정
    (원 / 부채꼴 / 직선)을 함께 지원.
  - 전투 공식을 상태 없는 Combat 모듈로 분리해 플레이어·몬스터가
    같은 공식을 사용: 치명타(확률·배율), 방어력 감소, 공격속도에 따른
    쿨타임, 스킬 수치(고정값 / 공격력 비례), 회복량.
  - 스탯 계산: (기본 + 고정 합) × (1 + 비율 합). 직업·레벨 기본 스탯에
    장비 옵션을 더해 최종 스탯을 만들고, 변경 시 다시 계산.
  - 스킬: 쿨타임, HP·MP 비용, 스킬 효과 그룹(데미지, 회복, 도트, 디버프).
  - 몬스터 AI: 대기 → 추적 → 공격 → 복귀(리쉬 범위) → 사망 → 리스폰.

[아이템 / 보상]
  - 보상: 전체 지급 / 개별 확률 / 가중치 랜덤 방식의 보상 테이블,
    기여도에 따른 보상 분배.
  - 필드 드롭: 우선권 유지 시간, 소멸 시간, 줍기 거리·우선권·가방 공간
    검증.
  - 인벤토리: 고정 슬롯, 스택, 아이템 추가·제거·버리기·사용,
    변경된 칸만 저장·전송. 골드 획득·소비.
  - 장비: 장착·해제, 장비 옵션(기본 옵션 + 랜덤 추가 옵션),
    외형 장비 변경을 주변 유저에게 알림.
  - 레벨: 누적 경험치 기반 레벨 계산, 레벨업 시 스탯 재계산.

[기획 데이터(템플릿) 관리]
  - 존, 포탈, 몬스터, 스폰, 보상, 스킬, 스킬 효과, 레벨, 스탯, 캐릭터,
    아이템, 아이템 옵션을 CSV로 관리하고 테이블별 템플릿 클래스로
    서버 시작 시 한 번 로드.
  - 컬럼 이름 기반 접근으로 CSV 컬럼 순서 변경에 영향을 받지 않음.
  - 로드 시 값 범위와 테이블 간 참조(포탈 → 존, 스폰 → 몬스터,
    스킬 → 스킬 효과, 스탯 → 레벨 등)를 검증해 잘못된 데이터로는
    서버가 기동되지 않도록 처리.

[아이템 UID 발급]
  - [초 32비트][서버 번호 8비트][순번 24비트] 구조의 64비트 UID를
    서버가 직접 발급.
  - DB 왕복 없이 아이템을 즉시 생성하면서도, 재시작 후에도 겹치지
    않고 생성 시각·서버를 UID만으로 확인할 수 있어 아이템 복사 추적에
    활용 가능.

[계정 / 저장 / 안정성]
  - libsodium으로 비밀번호 해시 저장 및 검증.
  - 중복 로그인 시 기존 세션 종료 처리.
  - 접속 중인 플레이어를 주기적으로 나눠서 저장(분산 자동 저장),
    변경이 없으면 저장 생략.
  - 서버 종료 신호(Ctrl+C) 수신 시 모든 존의 플레이어를 저장하고
    남은 DB 작업을 모두 처리한 뒤 종료.

[부하 테스트]
  - 로그인 → 캐릭터 생성·선택 → 입장 → 이동·사냥·스킬·바닥 아이템
    줍기·부활을 자동으로 수행하는 봇 클라이언트 개발.
  - 접속 수, 초당 송수신 패킷·바이트, 사망·위치 보정·스킬 실패,
    레벨업, 줍기 성공·실패 횟수를 주기적으로 출력해 서버 상태를 확인.

5. 프로젝트를 통해 얻은 것
--------------------------------------------------------------
  - Node.js에서는 런타임이 대신 처리하던 스레드, 메모리, 객체 수명
    관리를 직접 설계하며 실시간 서버의 동작 원리를 이해했습니다.
  - 라이브 서비스 운영 경험(데이터 오류, 중복 접속, 저장 누락 등)을
    설계 단계부터 반영하는 습관을 가지게 되었습니다.


--------------------------------------------------------------
6. AI 도구 활용
--------------------------------------------------------------
C++ 학습과 개발 과정에서는 AI 도구(Claude, GitHub Copilot)를 코드
리뷰와 개념 학습에 적극 활용했습니다. 서버 구조와 주요 설계는 직접
결정했고, AI가 제안한 코드는 동작 원리를 검증한 뒤 반영했습니다.
또한 테스트용 데이터 생성, Unity 클라이언트 프로젝트 관리처럼 반복적인
작업에도 AI를 활용해 핵심 서버 개발에 더 많은 시간을 쓸 수 있었습니다.
